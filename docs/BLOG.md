# 博客：写作、阅读与互动

本轮开发日期：2026-10-27（Asia/Shanghai）。当前实现为 0.1.10；最新核验与发布阶段以 [BLOG_RELEASE.md](BLOG_RELEASE.md) 为准。以下说明实现和使用方式。

## 使用入口

- 网页博客：`/blog/`，门户导航中的「博客」。访客可阅读、搜索、按分类和标签筛选。
- 网页写作台：`/blog/?view=write`；文章管理：`/blog/?view=admin`。
- 收藏：`/blog/?view=saved`，也支持 `?saved=1`，门户「我的」提供快捷入口。
- 小程序：首页博客入口；「我的」也提供文章收藏入口。列表和阅读页位于独立 `blog` 原生分包，不使用 web-view。
- 分享：网页复制文章链接，小程序分享文章或复制对应网页地址。

0.1.10 的列表使用紧凑搜索、分类标签与整宽文章卡；有封面时显示左侧缩略图，无封面时正文占满整行。标题、摘要、时间分类和互动统计分层显示。手机阅读页提供固定的评论、分享、收藏与点赞栏，并预留安全区底距；评论入口定位到真实输入框。网页同时适配桌面与手机，写作管理和页内确认继续保留。

管理员使用现有悦创账号登录。已按所有者指定，将 `aiyuechuang@gmail.com` 配置为管理员邮箱，记录在根目录及 `cloudflare/pages/` 的 Wrangler 配置中。该邮箱须已通过本项目账号系统的邮箱验证；配置不会自动注册、绑定邮箱或修改任何账号。部署时沿用已有账号/GitHub App 配置，`BLOG_ADMIN_EMAILS` 是非密钥配置。

可用 `BLOG_ADMIN_EMAILS` 或 `BLOG_ADMIN_USER_IDS` 配置更多管理员，用英文逗号分隔；管理员可编辑全部博客文章和管理全部评论。两项均为空时关闭写作权限，普通账号不会自动成为管理员。未登录或普通账号可阅读已发布文章，登录后可点赞、收藏、评论及删除自己的评论。

## 写作与发布

写作台支持 Markdown、格式工具栏和预览。可以填写标题、摘要、分类、最多 8 个标签、HTTPS 封面链接，并选择是否允许新评论。正文支持标题、段落、加粗、斜体、删除线、代码、列表、引用、链接、图片和简单表格；原始 HTML 按文本显示。

文章先保存为云端草稿，再发布；也可以直接发布。草稿仅管理员可见，撤回后公开列表和文章链接均停止展示。关闭评论保留已有讨论，管理员和评论作者仍可删除相应评论。删除文章后，公开接口无法继续读取相关讨论和互动。

编辑内容自动保存为当前浏览器、当前账号的本机恢复草稿，云端保存成功后清理相应本机草稿。云端保存需要非空标题和正文。本机草稿不能替代云端保存；浏览器清理存储后无法恢复。云端文章使用独立编辑版本号；其他页面已更新时返回冲突，保留当前编辑文字供比较处理。点赞、评论和浏览量变更不增加编辑版本号。

小程序使用同一份内容排版模块，并把长文章拆为完整、安全的 HTML 片段逐次传输，避免一次性把正文和排版副本传入数据层。正文中的链接可通过复制网页文章地址在浏览器阅读。封面和正文图片使用作者填写的 HTTPS 地址，不新增图片上传存储。

## 阅读缓存与刷新

网页和小程序共用内存缓存引擎。同一次博客访问中，已读取的列表、分类搜索结果、文章、评论分页和账号写作权限可复用；重复请求合并为一次。文章列表按关键词、分类、标签、收藏模式和页码分别缓存，返回时保留筛选与位置；小程序保留已加载的多页列表、评论页和正文排版，返回时不重复传输完整长文。

- 首次打开网页、离开后重新进入网页（包括浏览器历史缓存恢复），以及从小程序其他栏目重新进入博客时重新读取；小程序从后台回到前台也会重建阅读缓存。博客内部列表与文章之间切换复用当前访问的数据。
- 网页点击「刷新内容」，小程序下拉刷新或点击错误重试，均强制读取最新内容。搜索或分类切换优先复用同条件的结果。
- 成功读取的数据有效期为 5 分钟；到期后的下一次读取会请求服务端。其他人新增文章、留言或互动可通过主动刷新、重新进入或缓存到期后的再次读取看到，不进行后台轮询。
- 本人的点赞、收藏、评论操作成功后立即更新已缓存文章和列表的对应计数。收藏变化后重新取收藏列表，评论变化后重新取讨论；发布、撤回或删除文章会清除相关内容缓存。编辑器始终读取最新文章及编辑版本。
- 浏览统计在当前访问内按账号、文章和 UTC 日合并成功请求；服务端继续按原规则去重。失败请求不记入成功缓存。主动刷新和重新进入仍可发起浏览上报，服务端不会重复计数。

缓存仅保留在当前运行进程内，最多 60 条、UTF-8 JSON 总量 3 MiB；按近期使用淘汰，过大结果正常读取但不缓存。内存压力或淘汰后可能再次请求数据。文章缓存不写入 localStorage、微信本地存储或数据仓库；现有本机恢复草稿与随机浏览标识继续独立保存。缓存按账号隔离，退出或切换账号会立即清空；迟到的旧读取不能回填新缓存，操作失败且结果不确定时会使受影响快照失效，避免显示错误的成功状态。

## 数据与隐私

使用现有 GitHub App，按本次明确指定将博客独立保存到私有仓库 `BrclioData/Brclio-Miniapp-Blog-Data`。该仓库默认分支为 `main`，可由服务端 `GITHUB_BLOG_BRANCH` 指定。不新增数据库、对象存储或账号体系。学习、儿歌和挑战仍使用原来的 `Brclio-Miniapp-Data`，博客不读取或回退到该业务仓库。账号会话仍来自独立 UserData 仓库，博客通过只读认证共享现有会话。

所有博客记录均为结构化 JSON，包含 `schemaVersion: 1`。服务端在读取和写入时均校验字段、类型、长度、容量和未知字段；正文是文章对象中的 Markdown 字符串。正式字段定义见 [JSON Schema](blog-storage.schema.json)，与 `web/blog-schema.mjs` 的校验定义保持一致；部署产物也提供 `/schemas/blog-storage-v1.json`。

- `blog/v1/catalog/{0-f}.json`：分片文章摘要目录。
- `blog/v1/posts/{id}/article.json`：文章正文、状态、编辑版本和计数。
- 同目录的 `reactions.json`、`comments.json`、`comment-{id}.json`：互动与公开讨论。
- 同目录的 `views-{day}.json`：当日访客去重摘要；`day` 按 UTC 日计算。
- `blog/v1/users/{userId}/favorites.json`：账号收藏列表。
- `blog/v1/rates/`：操作限流记录。

浏览标识是本机随机值，服务端只持久化带服务端密钥的摘要；登录后按账号每天去重。刷新不会重复计数，换设备或清理缓存可能重新产生访客标识。写入限流使用 IP 的摘要，博客数据中不保存原始 IP。浏览计数是应用内阅读计数，不代表经过第三方审计的独立访客人数。

评论公开展示昵称、头像和文字。公开文章及评论作者数据不返回邮箱、凭据或会话。草稿、未授权管理接口及已撤回文章均受后端权限检查约束。文章和评论删除只影响当前可访问内容；私有 Git 历史及不可公开访问的关联记录可能继续保留。正文外链图片会向对应域名请求资源。

## 当前容量和运行条件

文章上限 500 篇；标题 120 字、摘要 300 字、分类 40 字、标签 8×24 字；正文最多 100,000 字符和 5,000 行。每篇最多 1,000 条当前评论、各 5,000 个点赞和收藏、每天 10,000 个计数访客。评论最多 1,000 字，单账号每小时最多发布 10 条评论。

数据通过 GitHub API 读取和原子提交，适合当前个人博客的使用方式。每个请求最多发起 45 次外部存储请求，发生并发冲突或达到共享 API 配额时返回可重试错误；界面提供相应反馈。此实现不声明高并发访问能力。
