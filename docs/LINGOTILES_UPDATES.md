# 词了个词持续更新

`Brclio/brclio-lingotiles` 是学习功能的持续来源。本仓库负责悦学入口、手机网页布局、微信原生界面与平台能力适配。不要把目前接入的版本视为独立停止更新的副本。

当前来源提交以 [`SNAPSHOT.json`](../web/projects/lingotiles/SNAPSHOT.json) 为准。普通构建完全离线，不跟随远程 `main` 自动漂移；显式同步将一个确定的上游提交完整导入，再对网页与小程序分别验证和发布。

## 检查上游

```sh
# 显式联网，只检查并生成报告，不修改已接入的源码、资源或来源清单。
npm run sync:lingotiles -- --ref main
```

报告列出固定源提交、文件新增／修改／删除、导出接口变化、产品文档变化、依赖与构建配置变化，以及适配冲突。先阅读报告，后续应用时使用报告中的完整 40 位 SHA，避免检查和应用之间 `main` 再发生变化。报告不是“新增功能已适配”的结论。

工具从固定 GitHub 仓库读取 Git 对象并复算 blob 哈希；不执行上游安装脚本、构建命令或工作流，不自动安装新增依赖。`--source-dir` 可使用本地 Git 对象库离线演练，`--target-dir` 只用于隔离测试；参数详情见 `--help`。

## 应用已检查的提交

```sh
npm run sync:lingotiles -- --ref <完整的上游提交SHA> --apply
```

同步完整保留 `src/`、`public/`、`PRODUCT.md`、`DESIGN.md`，包含全部现有词库分片、查词索引、插图索引和实际图片；不只复制当前可见的一页。原字节保存于 `upstream/` 和 `public/`，`SNAPSHOT.json` 记录每个文件的来源哈希。源码与资源先在临时目录完成校验和适配，随后替换；失败会保留或恢复原目录。手工修改过的导入文件、生成网页源码和未登记的原始文件会阻止覆盖。

本项目的 `mobile.css`、网页入口、适配规则、原生页面和平台 runtime 独立保留。网页 `src/` 由上游与 [`adapters/web.json`](../web/projects/lingotiles/adapters/web.json) 重新生成，不能直接手改；补丁上下文必须唯一命中，缺失或重复即停止。原生构建使用相同的冲突检查。需要调整网页适配规则时，修改规则后显式运行 `npm run adapt:lingotiles -- --write`，检查生成差异后提交。

`adapt --write` 是明确覆盖生成目录的命令；先把任何 `src/` 手改迁移到适配规则，再执行。它与拒绝覆盖本地修改的 `sync --apply` 不同。报告输出也不能指向现有源码或普通文件；可重复写入本工具生成的报告，推荐保存在 `artifacts/lingotiles/`。

## 适配新功能

词库或插图独立更新时，可以沿用未变化的玩法审查基线。上游功能源码、界面、数据结构或 `PRODUCT.md` 发生变化时，原生构建会由 [`NATIVE_CONTRACT.json`](../web/projects/lingotiles/NATIVE_CONTRACT.json) 阻止，列出变化文件及受影响功能。同步程序不会自动批准这个审查契约。

维护者应逐项完成：

1. 对照上游产品文档和源码差异，补充原生页面、事件、规则导出、网络／存储／文件适配；有数据结构变化时检查旧进度、收藏和足迹的兼容性。
2. 检查新增依赖与构建入口。需要的依赖在本工程明确登记，不能假设仅复制 `src/` 就能自动支持新库。
3. 更新网页适配补丁；对新增按钮、弹层、长文本和图片检查 320px、390px 及桌面布局。保留按选择触发加载、失败重试和完整资源。
4. 更新功能对照、回归测试与原生契约的功能分配、来源哈希和 `reviewedCommit`。保留尚未完成的平台差异，不用批量改哈希代替功能审查。
5. 运行下面的验证。契约一致只证明已审查源码未漂移，不能替代实际操作或证明完全对齐。

```sh
npm run check:lingotiles
npm run build
npm test
npm run check:release
# 有运行行为或样式变化时，启动本地网页后验证完整学习流程：
LINGOTILES_BASE=http://127.0.0.1:8790 node scripts/verify-lingotiles-web.js
```

至少验证：经典及分级选关 → 记忆 → 三牌消除／失败撤回 → 结果 → 重玩 → 足迹持久化与导出；单词本中英文搜索、收藏、现有插图、发音和联网失败重试。存储变更应带旧数据读取测试。资源新增时逐项检查清单和实际文件，不能只检查总数不变。

## 发布与回退

网页与学习资源发布至现有 Pages 项目；部署前记录本次源码提交、源仓库提交和构建文件哈希，部署后校验生产资源与完整流程。小程序内置经典词、玩法、原生界面或 runtime 更新时，必须重新构建并上传微信开发包，不能依靠网页资源热更新获得这些代码变化。

纯词库／插图的兼容更新可随同域资源部署供现有客户端按需加载。更改资源 JSON 结构或删除旧客户端依赖的地址前，须验证旧小程序兼容，必要时保留旧资源版本并随新开发包切换。不要把任意上游结构变更直接推到旧客户端。

回退优先使用 Git 中上一组已验证的 `SNAPSHOT.json`、`upstream/`、`public/`、生成网页 `src/`、适配和原生契约；一起还原后重新构建、验证、部署。保留学习本机数据，不通过清除用户缓存修复升级问题。小程序代码回退按微信平台对应版本另行操作。

各发布阶段独立记录：本地构建、网页部署、微信开发包上传、体验版、审核、正式发布、iOS／Android 真机验收。最新事实见 [验收记录](LINGOTILES_VERIFICATION.md)，发布步骤见 [RELEASE.md](RELEASE.md)。
