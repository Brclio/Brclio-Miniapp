## 本次内容

- 摄影：FirstSight_Online 的 9 组 169 张真实摄影，包含婚纱 8 组 128 张、孕期 41 张。主包封面和四个摄影分包内置 JPEG 展示图；支持相册、大图和缩放，无外部原图网站或 web-view 依赖。
- 默认放松玩法：原生触摸和无限双人挑战，保留开始、GO、抢跑和胜利音效、静音、设置试听、彩头分类／随机／手填／密码与揭晓、TXT 自定义彩头、标题／玩家名／等待时间设置。默认单轮先响应决胜，抢跑则对方获胜；GO 后没有 5 秒超时或平局窗口。
- 原生界面与战报：按 Brclio Design System 为手机重设计。单局 600×900、无限汇总 600×1100，使用用户提供的真实小程序码，包含胜者、反应时间／抢跑原因、彩头及汇总数据。声控、麦克风、录音与回放按用户确认移除。
- 独立计分扩展：保留 1／3／5 分、35 ms 平局、5 秒无人响应超时、暂停与最近 20 场本机战绩，不替代默认玩法。
- 我的：可选共享账号和手动挑战备份／恢复；覆盖预览确认后才写入，仅同步计分扩展的白名单数据。原生账号页面、中央服务与 Pages 代理的证据分别验收。

功能与最新模拟器验证见 [READY_GO_DUEL_PARITY.md](READY_GO_DUEL_PARITY.md)。实体手机听感、扫码落地、软键盘、真实相册写入及实际分享仍需单独验证。

## 版本、构建与包体

上传前将 `package.json`、锁文件根版本、小程序配置及网页目录版本统一到 `0.1.1`，再串行执行：

```sh
npm run build
npm test
npm run check:release
```

功能代码已提交并推送的 `1a2e812` 是版本更新前的功能基线；上传记录应填写包含 `0.1.1` 配置更新的最终 Git 提交，不把旧提交当作最终上传包指纹。

普通构建离线运行，不需要访问私库或配置 Secret。原生相册维护模板为 `native/album/`；构建会同步摄影分包，勿手改生成页面。更新照片时先按 [来源说明](../web/projects/firstsight/SOURCE.md) 显式同步，再运行 `npm run prepare:photos`。

核对主包及每个摄影分包低于 2 MiB，全部代码与素材低于项目 20 MiB 预算；来源图、展示图和封面分别与各自清单一致。AppID、普通小程序类型与 `urlCheck: true` 保持准确。原生报告只引用 `miniprogram/assets/duel-miniprogram-code.jpg`，不能换回网页二维码。

上传成功后，在微信后台选择本次 `0.1.1` 开发包设置体验版，并在 iOS／Android 微信检查：

- 摄影筛选 9／8／1、169 张照片、孕期 41 张；相册切图、缩放、边界、返回和分享正常。
- 默认触摸开始音、等待、GO、先响应、抢跑和胜利反馈正确；故意晚于 5 秒触摸仍能决胜。无限模式可自动换彩头、继续下一轮、退出汇总和生成总战报。
- 标题、双方名字、随机设置、等待时间、彩头分类／密码／揭晓和 TXT 导入可用；小屏与软键盘不遮挡输入或底部操作。

- 计分扩展的 1／3／5 分、平局窗口、5 秒超时、后台取消、本机历史和清除单独正确。
- 共享账号注册／登录／失效、资料与密码更新、退出正常；退出保留本机挑战。备份／恢复显示目标账号、数量与覆盖方向，取消不写入，冲突保留本机；恢复前副本和跨账号隔离有效。

## 提交审核与正式发布

用户已授权提交本次小程序审核。但此前 Computer Use 对 `mp.weixin.qq.com` 返回明确访问限制，用户自行打开的后台标签同样不能由自动化接管。因此本轮自动操作范围最多完成开发工具上传；微信后台的体验版设置与提交审核由用户接管。该限制不表示用户尚未授权，也不能通过换标签或其他入口绕过。

用户在后台继续时：

1. 确认开发版本为本次 `0.1.1`，不要误选上次 `0.1.0`。
2. 按实际摄影、反应挑战、账号和战报保存能力核对类目、备案、隐私指引、相册用途及 request 合法域名；账号域名为 `https://pocket.bornforthis.cn`。历史类目「生活服务 → 婚庆服务」不自动证明覆盖反应玩法。
3. 完成后台要求的审核资料后提交，保存平台显示的提交时间、审核版本和状态。
4. 审核通过后，再按用户安排执行正式发布；审核通过与正式发布分别记录。

已记录的上传成功只证明开发包阶段；“已提交审核”“审核通过”和“已上线”必须另取平台证据。
