# 用户头像

2026-10-25 新增；本文件记录本地实现与验证，不代表线上部署或微信发布已完成。

网页「我的」点击头像，小程序「我的账号」点击「设置头像」，可以选择 1000 个内置头像、随机更换或上传自定义图片。每页显示 40 个，共 25 页。新注册账号随机分配头像；此前没有头像的账号在登录或刷新会话时补齐一次。头像保存在账号资料中，再次登录与切换设备沿用该选择。

## 图片与存储

- 内置头像为 10 类原创角色的配色、配饰变体，固定编号 1–1000，160×160 PNG，全部约 3.65 MiB。通过现有网页域名 `/avatars/0001.png` 至 `/avatars/1000.png` 按需获取，不打包进小程序。生成方式和来源见 [内置头像说明](../design/builtin-avatars/README.md)。
- 上传支持 JPG、PNG、WebP、GIF，原图最多 10 MiB、4000 万像素，单边最多 16384 像素。原始文件不经过画布或重新编码，保留所选文件的完整字节，并记录 SHA256。此处原图指浏览器或微信照片选择器实际返回的文件。
- 客户端另行居中裁切并生成 256×256 JPEG 展示图，最大 128 KiB。透明区域填暖色底，GIF 展示静态画面。网页提供保存前预览，小程序在照片选择后处理并保存。
- 原图和展示图均使用已有私有仓库 `BrclioData/Brclio-Miniapp-UserData`，路径为 `users/v1/{用户前两位}/{用户ID}/avatars/{随机版本ID}/original.{扩展名}` 和同目录 `display.jpg`。头像元数据写入该用户 `profile.json`。使用现有 GitHub App，不新增存储服务或 Secret。
- 两个图片 Git blob 与用户资料通过同一 Git tree/commit 更新分支；冲突时重新验证会话和用户资料后重试。上传失败不切换头像。更换头像保留以前的原图与压缩图，Git 历史也可能保留旧版本。

## 接口

`PUT /api/account/avatar` 要求当前账号 Bearer 会话，仅修改当前用户，每小时最多 30 次。切换内置头像传 `{ "builtinId": 1 }`。自定义头像传两个对象 `original` 与 `compressed`，各有 `mimeType` 和无 data-URL 前缀的 base64 `data`。服务端检查类型、文件签名、尺寸和大小，成功返回 `{ "user": ... }`。

会话和登录响应的安全用户资料包含 `avatarType`、`avatarId` 和同源绝对地址 `avatarUrl`。内置头像的 `avatarId` 是固定编号，自定义头像为 `null`。用户目录和原图信息不会进入公开资料。

`GET /api/account/avatar/{用户ID}/{随机版本ID}` 只提供 JPEG 展示图，供图片组件加载；持有完整地址的人可以访问。原图没有公开读取接口，也不会出现在头像展示地址中。未知版本、无效用户及其他路径不能读取文件。账号客户端防止迟到的上传或会话刷新恢复旧账号、覆盖刚刚保存的头像。

## 本地验证与发布边界

- `npm test`：512 项测试通过，覆盖已有功能及头像编号与唯一性、账号鉴权和隔离、持久化分配、原图字节、格式和大小限制、Git 提交失败和冲突、原生图片处理、网页预览与迟到请求。
- `npm run build`、`npm run check`：通过，1000 个头像进入网页产物，小程序主包仍小于 2 MiB。
- 本地 Chromium 实测使用构建产物、真实账号 API 和内存仓库替身，完成随机补齐、内置切换、自定义预览、实际 Canvas 压缩、逐字节原图比对、JPEG 加载、刷新恢复以及 390px 宽度检查。此过程没有写入真实用户仓库。截图保存在本地 `artifacts/avatar-desktop.png`、`artifacts/avatar-mobile.png`。
- 未部署 Pages，未上传或发布微信版本，未声称真实 GitHub 上传成功。微信后台照片选择隐私声明与真机的允许、拒绝、取消、GIF/方向兼容性仍需发布前实际验收；更新的声明素材见 [微信隐私填写说明](WECHAT_PRIVACY_FILLING.md)。
